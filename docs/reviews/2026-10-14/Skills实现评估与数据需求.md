# Skills 实现评估与完整实现数据需求

评估日期：2026 年 10 月 14 日。范围为当前工作区的四领域技能集市、服务端全部技能定义、Python 算法、地图渲染、主线 Agent 与持久业务工作流。场景基准为 [四智能体功能清单](../../../plan/人工智能-四智能体-功能清单.md) 第 23 至 76 项；历史流水线方案只作为设计目标。

当前实现具备统一执行、权限控制、数据来源、有限真实计算和地图组合基础，但尚不满足全部专业场景。应继续补齐业务数据、模型验证和工作流数据契约。最优先的工作是修正能力展示与统计语义、修复已复现的问题，再建设可组合的科学计算能力。

## 第三阶段落实状态

第三阶段已实现持久科学 DAG 编译与执行、节点子时间窗、类型化条件分支、有限重试、取消、租约恢复和显式检查点恢复。扫描与 K-Means 接入科学工件，新增 ScanResult/ClusterSet；扫描成员→SelectionSet→FeatureMatrix→聚类→固定成员长历史链路可执行。最新规则、数据与剩余任务以 [第三阶段交付与剩余任务](第三阶段交付与剩余任务.md) 为准；下方第二阶段及原评估是历史基线。

原 `skill_composable_workflow` 改为可调用的受限科学 DAG，标记 partial/contract，兼容 `skill_scientific_dag` 别名；新增四个原子工件技能。集市当前 68 个公开 ID、104 个展示位置、1 个内部 ID，仍有 17 个 planned ID/19 个 planned 展示位置。LSTM 与完整 SaTScan➔K-Means➔LSTM 能力保持 planned/unvalidated；没有合格权重和真实来源回测，不产生预测。近似扫描与探索性聚类的工程验证不替代官方实现对照、K 选择或专业风险验收。

近期成员可在根授权历史内回取长序列，前提是准确关联同一 Measurements 快照、成员子集和覆盖历史的测量工件，且成员形成时点不晚于序列截止。Worker 重取当前认证身份，并以租约 token 防止失联进程覆盖检查点。独立工件有效期为 24 小时，持久 DAG 工件固定为提交起七天，恢复不延长。计划的来源元数据或已完成工件改变/过期都会拒绝继续使用。

已修改 Mock 生成器并补充隔离数据包 `.mock-data/phase-three-scientific/`，明确原始访次与 trap-hour 投入、完整月历史及可重复多成员热点。新适配器只在已审计 Mock 快照中消费这些明确资料，不猜测 observed 的旧 sampling_unit，默认 observed 来源未切换。实跑得到 4 个固定地点、3 个探索性簇、8 条各 82 个月的序列，共 656 个有限值；独立进程的取消恢复验证复用了原检查点。见 [Mock 链路证据](phase-three-evidence/mock-dag.json) 和 [跨进程恢复证据](phase-three-evidence/process-restart.json)。这不是现实效果验收。

相关测试和静态检查见 [第三阶段验证汇总](phase-three-evidence/summary.json)。部署新增 `011_scientific_dag.sql`；来源数据库的只读及 Mock 生命周期门禁继续生效。当前剩余重点是专业分母/真数据接入、扫描独立科学对照、K 和特征验证、LSTM 权重及滚动回测、专业端到端验收、工件归档共享与运维。

## 一 结论与范围

1. 集市有 **47 个不同技能 ID**，在四领域中共 **51 个展示位置**。其中标记 planned 的技能共有 **18 个不同 ID、20 个展示位置**：病媒 8 个、食源 3 个、环境 5 个、慢病 4 个。同一 `skill_spatial_early_warning` 在病媒可用，在其余三域尚未实现，因此统计以领域和 ID 共同确定状态。
2. 服务端共有 **58 个公开技能 ID 和 1 个内部技能 ID**，合计四域 98 条定义。集市缺少的公开 ID 有 11 个，包括回测、地图、任务、审批、复测等；“全部 skills”评估必须包含这些能力。
3. `available` 只代表受限方法能执行。AR 捕获量预测、抗药性记录查询、IDW 插值、死亡记录统计等均不能代替原需求中的标准密度预测、抗药性推断、疾病风险预警、死亡率和寿命表。
4. 原 SaTScan ➔ K-Means ➔ LSTM、LSTM 单技能、旧动态组合图明确返回不可用。当前主线支持多次调用技能并读取结果，但没有通用科学数据引用、类型匹配、DAG 依赖和节点恢复机制，不能视为已恢复完整科学流水线。
5. 地图解耦方向合理：行政底图、空间输出、地图组合和渲染分别实现。热度图、插值网格、区域色块和扫描圆有独立表示；仍需补齐空间验证、插值适用域、时间和指标可比性，以及专业预警层。

上述数量来自当前工厂实际导出的 [技能清单](skills-audit-evidence/inventory.json)，按 `inMarketplace` 字段统计，未把按钮数量、历史文件或算法 task 名称当作完成数。

## 二 所有技能的场景符合性

本节的“部分”表示实现了受限子功能；“未实现”对应 planned；“基础可用”表示当前工程职责有实际实现，仍需在真实机构环境验收。准确率、时效和科学效果不能由工程测试通过直接推导。

| 技能 ID | 当前实现 | 对完整场景的判断与改进 |

| `skill_population_dynamics` | 按采样方法分组的月捕获量 AR 与季节项 | 部分。没有完整 ARIMA/LSTM、气象驱动和预测区间；目标是 captures/record，需规范投入分母后预测标准密度。 |

## 三 热力图与空间功能专项评估

### 已实现且应保留的边界

- `SpatialOutput` 携带 runId、callId、skillId、数据来源、范围指纹、坐标系、指标单位与精度。组合图按授权来源、范围及支持的 rendering 校验，失败图层有独立状态。
- 行政底图不依赖监测数据。区域汇总用真实边界，区县中心点明确标记 `administrative-centroid` 并禁止 heatmap。
- IDW 返回观测点与派生网格，扫描半径通过测地圆绘制；点位支持数值映射大小。缺几何、负权重、无单位、来源越权及载荷超限有防护。
- 实测水质 HQ 点图已经有适配器，不能将它称为 Kriging 风险面；污水滞后只提供区域标签，不能凭厂名猜测溯源几何。

### 需要补齐的空间语义与验证

| 问题 | 当前证据 | 完整实现建议及验收 |
|---|---|---|
| 热力颜色容易被当作风险等级 | heatmap-color 使用屏幕像素的 heatmap-density，而不是专业阈值；权重直接取 value，半径固定 25 像素 | 分别命名“点位热度”“插值估计”“风险等级”。热度图用相对密集程度图例，专业风险用经过审批的阈值色带；记录权重归一化和缩放参数。 |
| IDW 在稀疏区域也生成连续值 | 当前全点逆距离平方，在点位外包矩形生成网格，没有最大距离、邻点数量门槛、凸包或辖区掩膜 | 仅在支持域输出：点数及覆盖度门禁、最近距离上限、凸包及行政边界裁剪；无支持区域为 NoData。阈值通过空间交叉验证确定。 |
| 网格分辨率不能保证街道精度 | 默认 18×18 经度纬度网格，渲染裁至矩形；底图层级只到县 | 采用米制投影中的格网，登记真实街道边界、采样覆盖与定位误差；网格细化不能代替地面验证。 |
| 插值缺少误差证据 | 当前 flag 明确无插值不确定性评估 | 增加留点/空间分块交叉验证，比较 IDW、Kriging 和简单邻域基线；输出 MAE/RMSE、覆盖度和可信范围。 |
| 数值颜色共享范围未包含时间及滤项 | composeMap 按 method、unit、definition、semantics、precision 分组色域 | 加 measurementDefinition、时间窗、采样方法、物种与统计分母；用户显式比较时提供共同色域，否则保持独立图例。 |
| 地图上的数量可能被截断 | 交互查询最多 200 行，适配器以 returned-rows-may-be-limited 提醒 | 全域热力图使用专门的空间聚合/瓦片接口；显示总数、返回数和截断状态，禁止把前 200 点解释为全省。 |
| K-Means 成员点不稳定 | 当前成员缺 location_id，clusterId 按每种方法从 1 重启 | 用稳定 location_id/species_id/method_id；cluster ID 包含模型和方法。展示模型特征及聚类性质，不自动贴高风险标签。 |
| 水质同一站点多个日期叠点 | observedPoints 为记录级，同坐标会重复计权 | 提供最新值、期间均值或超标次数等明确聚合模式，分别对应单位、时间窗和真实站点 ID。 |
| 地图质控与风险触发尚未贯通 | rendering 支持不等于 alert 输出，病媒 alerts=[]，三域公共技能 planned | 独立 `risk.evaluate` 产生阈值、政策版本、证据 ID 与置信度，再由地图渲染离散风险图层。 |

MapLibre 官方定义 `heatmap-density` 为像素级核密度的相对聚集度，不能直接解释成病媒标准密度或疾病发生概率。[MapLibre 表达式规范](https://maplibre.org/maplibre-style-spec/expressions/)

## 六 18 个未完成技能的完整实现方案

每个技能交付均包括：输入输出 schema、数据及权限门禁、算法/规则实现、结构化结果与界面、可重放证据、独立测试及业务验收。以下列出专业差异，通用串接框架见第七节。

### 1 跨领域空间预警 skill_spatial_early_warning

**现状**：病媒有捕获量插值，食源、环境、慢病共三个 planned 展示位置。D1/D2/D3/D5/D6 提供可定位的观测及分母；D8 提供阈值与响应政策。

**实现**：保留旧 ID 为场景入口，内部使用 `measurement.aggregate` → 可选 `spatial.interpolate` → `anomaly.detect` → `risk.evaluate` → `map.compose`。食源按真实事件地点/行政区分布；环境分别评估水质、空气和流域；慢病展示标准化群体率或脱敏群体风险。每个告警输出 alertId、指标值/分母、时间窗、触发规则及版本、证据引用、级别和适用区域。

**验收**：全部三域的真实输入可进入对应适配器；没有坐标则只呈现授权区域汇总，没有标准密度则只给捕获量；15 分钟要求按数据可用至告警产出的链路定义和实测，街道精度另验真实坐标、边界与覆盖。三种图层不能互相冒充。

### 2 分级推送 skill_alert_push_dispatch

**数据**：D8 的风险政策、组织层级、授权接收人、手机号/设备凭据、退订/偏好、事件 ID 和渠道回执。

**实现**：独立 `alert.classify`、`notification.route`、`notification.dispatch`；复用 outbox，增加短信/APP 适配器、幂等键、退避、死信和回执处理。级别按业务规则确定，LLM 只能解释依据。

**验收**：真实渠道沙箱或测试收件人逐一核对；重复事件不重复发，失败可重试，状态分别标记排队、供应商接受、送达及失败。审批与接收辖区须经服务端验证。

### 3 消杀闭环 skill_disposal_workflow

**数据**：D8 专业处置 SOP、适用媒介/生境、禁忌、人员/机构、执行证据及复测标准；D1/D4 测量和药剂证据。

**实现**：`advice.retrieve` → `disposal.plan` → 人工审批 → `ticket.dispatch` → 执行记录 → `retest.evaluate` → `ticket.close`。复用现有 Job、审批、工单和真实采集证据，新增领域政策，建议与执行分离。

**验收**：缺 SOP 或测量政策不进入核销；复测须一致物种、方法、单位、地点和规定时间，并留存结果；工单关闭与区域风险解除分别判定，支持重开、超时升级和完整审计。

### 4 抗性演化 skill_resistance_evolution

**数据**：D4 至少多个时间点的同一群体基因型、样本量、药剂使用及迁移/生境；D10 的独立后续基因频率或生测结果。

**实现**：先计算等位基因频率及区间，再建立分层贝叶斯时序/网络模型，明确药剂选择压力、空间群体和不可识别参数；预测未来一年频率、区间和变化概率。保留生测表型为独立输出。

**验收**：训练诊断、后验预测、时间与地点留出、区间覆盖率和简单持续性基线比较；无基因样本时返回数据不足，不从死亡率生成 KDR。

### 5 知识问答 skill_vector_nlq

**数据**：D7 版本化监测规范、物种鉴别、方法标准、专家审核问答；语音需真实音频和转写评测，数据库问答沿用受控仓库。

**实现**：独立知识检索 → 条文及适用性校验 → 带页码/条款的答案；数值查询调用 Text2SQL。语音转写是可选入口，不混在检索模型中。每个引用能定位原始条文，冲突或过期规范显式提示。

**验收**：专家问题集检索召回、引用正确率、答案忠实度及拒答；针对需求的端到端 2 秒目标测真实冷/热缓存及并发，必要时使用索引缓存和结构化条文快速回答，不能只测检索时长。

### 6 移动识别与采集 skill_mobile_assistant_api

**数据**：D7 多设备、姿态、背景与物种的专家标注照片及困难负例；D1 采集表单、方法单位规则；D8 用户和任务。

**实现**：`species.identify` 输出候选/置信度/拒识 → 人工确认 → `collection.prefill` → `collection.validate` → 幂等提交。图片对象存储与权限控制；需要离线时实现本地队列、重传和冲突处理。接入真实视觉模型和 API 文档。

**验收**：按类别和设备独立评测、未知种拒识、低置信度人工复核；零捕获、缺投入、重复提交和断网恢复；识别未确认不得自动写成专家确证。

### 7 LSTM 单技能 skill_lstm_predictor

**数据**：D1/D2 连续等间隔的目标序列、投入和天气；D10 权重与回测。日、周、月模型分别配置，不能把月监测序列直接用于下一周预测。

**实现**：先完成目标密度/捕获量定义和缺测策略；训练服务与在线推断分开，注册 scaler、特征、窗口、频率、训练截止和权重。优先基线比较，增加区间估计、缺测及分布漂移门禁。BiLSTM 只能编码预测起点前的历史窗口，不能接触未来标签。

**验收**：滚动起点、地点外部留出、多步误差、季节基线和区间覆盖；需求“≤10%”必须先固定误差指标、目标、零值处理和预测跨度，再在独立真实数据上验证。失败模型保持未验证状态。

### 8 科学流水线 skill_satscan_kmeans_lstm

**数据**：D1/D2 的一致地点 ID、扫描暴露分母、逐期历史和天气；D10 的 SaTScan 对照与预测权重。热点月之外仍要有热点成员的足够历史。

**实现**：提取数据 → 正式扫描/标明近似扫描 → 保留成员集合 → 生成成员特征 → K-Means → 按固定成员回取历史 → LSTM → 回测证据与地图。K-Means 可选；科学上不应为凑步骤强制插入无解释收益的聚类。

**验收**：簇成员与输入完全一致；零热点分支明确跳过预测，不把“未发现显著簇”说成无疾病风险；少样本、失效模型和取消分别处理，端到端重放可追踪每个节点。

### 9 通用组合 skill_composable_workflow

**数据**：无新的原始事实要求；需要各技能 schema、ArtifactRef、输入输出类型、模型/政策版本、权限及持久运行存储。

**实现**：自然语言产生候选 DAG，服务端编译类型及权限，执行器仅调用统一 executeSkill。支持依赖、条件、并行无依赖分支、人工节点、有限重试、取消、检查点与失败恢复；不执行任意上传 Python/SQL。每条边引用服务器保存的结果。

**验收**：至少支持扫描→预测、质控→统计→报告、病例→分子簇→建议等模板；错误类型、跨用户/域引用、过期数据、越界子集和未验证模型必须拒绝；持久恢复不重复写入或发送。

### 10 食源风险预测 skill_foodborne_risk_forecast

**数据**：D3 发病日、病原类别及缺检状态、暴发金标准；D2 气象和预报；D5 人口/报告率及交通流动，需覆盖多个季节和地区。

**实现**：分开病例计数预测、病原类型概率、暴发事件评分和扩散情景；用计数基线与 LSTM 比较，校准风险等级，缺少病原标签时只做病例趋势。输出地区时间风险及模型适用范围。

**验收**：时间/地点留出、计数误差、事件召回及误报、病原概率校准和预警提前量；Mock 仅验证接口与极端分支。

### 11 食源处置 skill_outbreak_disposal_advice

**数据**：D3 事件病例、场所、食品批次、分子及流调证据；D7 专业 SOP 和历史案例；D8 机构、处置与审批。

**实现**：事件证据摘要 → 经验证的规范/案例匹配 → 建议计划 → 审批与工单。封存、采样、流调和复检步骤分别有对象和证据；供应链源头保持候选/确认状态。

**验收**：专家盲审建议适用性、引用及禁忌；跨辖区协作、重试与结案复核。没有流调证据时不把 cgMLST 候选簇称为确证源头。

### 12 环境 OCR skill_env_ocr_entry

**数据**：D7 水质化验单、空气报表、污染源台账原件和字段/表格标注；D6 指标词典、单位和检出限；D8 录入权限。

**实现**：上传/文件校验 → OCR 版式解析 → 字段与单位映射 → 质控 → 带原图位置的人工修订 → 幂等入库。保留原始识别、修订和值转换过程；PDF、手机图片和电子表格分适配器。

**验收**：分版式的关键字段准确率、单位转换、表格结构、LoD/未检出识别；低置信度阻止自动入库；每个最终值可回到原件。

### 13 空气气候健康 skill_air_climate_health_risk

**数据**：D2 逐时/逐日污染、气象观测和 72h 预报；D5 年龄人群、活动模式、就诊/死亡序列、节假日和医疗报告覆盖；D10 暴露与结局验证。

**实现**：暴露估计 → DLNM 滞后非线性关联 → GBDT 或其他预测模型 → 72h 脆弱人群预警 → 独立建议。预警使用起点时已发布预报；解释性关联与预测模型分开。

**验收**：季节、趋势、星期和其他污染物调整；时间外验证、关联区间、预测误差、事件召回/误报及 72h 提前量；没有活动数据时只报告环境浓度代理，不能称个体真实暴露。

### 14 环境情景推演 skill_env_scenario_simulation

**数据**：D6 源清单、排放、扩散/管网参数和暴露；D5 基线疾病率；D9 干预、对照和效应/经济参数。

**实现**：场景定义 → 源削减到浓度变化 → 浓度到暴露 → 健康效应函数 → 受益人数/疾病负担区间。参数目录注明适用人群、时间、来源和外推限制。

**验收**：零削减恢复基线、剂量单位及质量守恒、敏感性与不确定性分析、历史真实干预外部验证；没有效应依据时只预测环境变化，不编造发病下降百分比。

### 15 环境闭环 skill_env_early_warning_disposal

**数据**：D6 水质/空气/河流源及网络；D8 三类触发规则、干预 SOP、机构、执行和复检。

**实现**：分别阈值/趋势/联合预警 → 风险与来源候选 → 建议 → 工单 → 领域复测与审批。与病媒共享通知和状态机，指标、单位、解除门槛和证据由环境插件提供。

**验收**：超标实时链路、上升趋势与多因素叠加有独立样例；水质复检和空气持续时段各自验证；拓扑缺失时不得锁定污染源。

### 16 慢病风险 skill_chronic_risk_forecast

**数据**：D5 含未发病人群的纵向队列、危险因素、家族史、既往病史、首次事件、失访、死亡/删失及人群分母；D10 机构和时间留出。

**实现**：个体风险 GBDT/生存模型、区域发病率时序、并发症规则三个原子技能；校准并提供绝对风险时限。病例 complications 字符串的共现统计可作为探索，不能替代随访和因果结论。

**验收**：需求 ≥80% 需明确 accuracy 的任务、类别比例和阈值，同时评估 AUROC/AUPRC、校准、敏感度和亚组；生存模型评估删失下的指标；跨机构外部验证后再应用。

### 17 精准筛查收益 skill_chronic_screening_roi

**数据**：D5 人群资格、既往筛查、诊断与随访；D9 检测性能、参与率、分期转移、真实成本、效用和资源容量；D8 清单访问政策。

**实现**：资格筛选 → 已验证风险分层 → 资源约束下推荐清单 → 决策树/Markov 筛查情景 → CEA、预算影响和区间。成本效果、财政 ROI 与单纯病例数排行分别呈现。

**验收**：与人工推荐清单核对，重复及过期资格剔除；收益按同一时间/价格/视角计算；增量成本和效果可复算，包含敏感性及外部校准。

### 18 慢病预警闭环 skill_chronic_early_warning_disposal

**数据**：D5 真实急性事件、死亡/伤害序列及人群分母；D7 三类干预规范；D8 分级、接收机构、资源及处置反馈。

**实现**：阈值/时序/关联检测 → 分级路由 → 死因/慢病/伤害各自建议 → 专业审批和工单。统计异常与确证事件保持不同状态；机构容量和就诊延迟是输入证据。

**验收**：一般/较重/严重三类接收路径、三种干预对象、敏感信息权限和结案复核；没有可信趋势模型时只生成已验证阈值候选，不输出 LSTM 趋势预警。

## 七 技能解耦与科学流水线设计

### 当前边界与拆分原则

当前 `SkillDefinition` 提供通用 JSON 输入输出，`SkillResult` 保存运行、数据源、状态及质量标记，这是合适的统一入口。主线把工具结果加入模型上下文，以最多 3 个工具批次、8 次调用执行；大数组还会摘要。这适合短交互，不能可靠传输完整特征矩阵和长期科学任务。`SpatialOutput` 已采用来源引用方式，可作为科学 ArtifactRef 的设计基础。

建议形成三层：领域原子技能负责一种数据变换；共享工程技能负责执行、权限、通知、报告和地图；场景技能负责一个经过验证的组合模板。保留现有 ID 和别名兼容，新增原子 ID，通过 capability metadata 声明输入类型、输出类型和组合条件。

| 当前捆绑 | 建议原子技能 | 保留的用户入口 |
|---|---|---|
| 物种构成与 K-Means | `species.composition`、`species.diversity`、`features.build`、`cluster.kmeans` | 优势种群分析 |
| IDW 与预警 | `measurement.aggregate`、`spatial.interpolate`、`anomaly.detect`、`risk.evaluate`、`map.compose` | 空间预警 |
| AR/GBDT/LSTM 各自读取库 | `series.build`、`forecast.predict`、`forecast.backtest` | 趋势预测，算法作为受控参数 |
| 水质风险与预测热图 | `water.compliance`、`exposure.estimate`、`risk.toxicology`、`forecast.predict`、`spatial.interpolate` | 饮用水健康分析 |
| 污水相关与溯源 | `sewage.normalize`、`series.lag_association`、`network.trace_candidates` | 污水疫情关联与溯源 |
| 分子同源与源头 | `molecular.distance`、`cluster.single_link`、`supply_chain.link`、`outbreak.evidence_review` | 食源联合溯源 |
| 死因质控与编码 | `certificate.qc`、`cause.extract`、`icd.select`、`coding.review` | 死因审核 |
| 个体预测与群体趋势 | `risk.individual`、`incidence.aggregate`、`forecast.population`、`association.mine` | 慢病综合分析 |
| 筛查和 ROI | `screening.eligibility`、`screening.prioritize`、`economics.evaluate` | 精准筛查 |
| 报告中嵌算法 | `report.compose` 消费已核验结果，`artifact.export` 负责文件 | 专题报告 |
| 专业闭环 | `advice.retrieve`、`ticket.dispatch`、`retest.evaluate`、`ticket.close` | 领域处置 |

四个 SQL 构建器/查询技能可以共享实现而保留领域入口；单个 Skill 同时拥有业务含义和正确权限边界，比机械按文件数拆分更重要。聚类模型不是风险分级规则，报告不是计算引擎，推送不是预警算法。

建议在现有 SkillResult 之外增加版本化结果工件，矩阵和序列保存于服务端，LLM 只传引用与已审核参数：

### SaTScan ➔ K-Means ➔ LSTM 的具体串接

```mermaid
flowchart LR
  A[授权监测数据与投入] --> B[按地点和时间生成 ScanInput]
  B --> C[正式 SaTScan 或明确标注的近似扫描]
  C --> D[ClusterSet 和稳定成员 SelectionSet]
  D --> E[成员特征矩阵]
  E --> F[可选 K-Means 亚群]
  F --> G[固定成员的完整历史 SeriesSet]
  D --> G
  G --> H[已验证 LSTM 推断与区间]
  H --> I[报告与预测图层]
  C --> I
```

1. **提取**：统一地点、物种、采样方法、投入分母和截止时间。扫描月、模型训练历史和预测跨度是三个不同参数；允许历史窗口更长，但不能越过用户批准的使用范围。
2. **扫描**：病例 Poisson 扫描使用人口/人时等相应暴露；病媒捕获扫描先验证采样投入与统计模型适配。要声称完整 SaTScan，应对照官方实现验证模型、时间窗、Monte Carlo、LLR、RR、成员及输出解析，不能只复用同名函数。官方教程区分空间/时空模型，并强调人群、窗口、网络及信号设计。[SaTScan 官方教程](https://www.satscan.org/tutorials.html)
3. **聚类**：对象是监测点或经明确定义的子区域；特征包括可比较密度、物种构成、生境和天气等。预处理只在训练数据拟合，K 根据稳定性、轮廓等选择；簇编号不能自动成为风险等级。
4. **序列构造**：按扫描输出的 location_id 形成固定成员集合，回取成员完整历史，而不是把 affected_cities 传给 LSTM 后重新读取整个城市。明确访次、分母和汇总权重；缺测不填为零，成员变化需版本化。
5. **预测**：使用已注册模型，只消费起点之前的序列和当时已发布的预报。每个回测起点重新执行扫描、特征选择和聚类，避免用未来发现的热点回测过去；训练和测试预处理严格隔离。[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html)、[时间序列切分](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
6. **分支和恢复**：无显著簇为扫描的合法结果，后续节点标记 skipped 并说明原因；样本不足不给预测，模型缺失则失败。持久记录节点状态、输入输出哈希、错误与取消。计算节点可恢复，工单/通知节点按幂等键防重复。
7. **长任务**：主线 Agent 选择模板或提交已编译 DAG；Worker/LangGraph 确定性执行并支持人工检查点。不要简单放大 8 次工具预算来替代编排。节点事件含 workflowRunId/nodeId，界面可查看等待、执行、失败和已完成结果。

另外应提供两类模板验证通用性：水质 OCR → 标化 → 合规 → 风险 → 预警 → 工单；病例聚集 → 分子候选 → 供应链证据 → 人工研判 → 简报。跨领域连接必须有实际地点/对象映射和授权，不只共享中文地名。

### 集市之外还缺少的原始需求

`skill-requirements.json` 未直接覆盖需求 **43 数据清洗标化、48 公共场所健康映射、49 动态卫生评级、58 移动离线任务**。这些能力应新增可发现的原子/场景技能，不能只补现有 planned 项后宣布 54 项需求全部完成。

- 43：建立 `data.standardize` 和 `data.quality_review`，需要单位/编码字典、缺失策略及可保留原始值的转换日志；插补只在合适分析流程内执行，不覆盖原始观测。
- 48、49：提供 `venue.health_mapping`、`venue.rating`，需要场所类型、完整检查项目、评分细则版本和实测健康证据；当前 80 条 Mock 与已有评级字段不足以验证评分或健康模型。
- 58：提供环境采样任务、扫码、附件上传和离线同步，沿用移动采集架构但使用环境指标及单位 schema。
- 40、56、73 等已有需求映射仍不完整：动态大屏需要实时聚合和钻取，周期报告需要调度，自定义模板需要独立管理、版本及固定格式导出。需求映射只是追踪关系，不能当作实现证据。

## 九 实施顺序与验收交付

阶段工作量为排期起点，实际取决于数据接入与专家验收；模型效果没有可靠的固定工期承诺。

| 阶段 | 交付 | 依赖与退出标准 |
|---|---|---|
| 第一阶段 修正当前质量 | 水质空值与计数、能力名/说明、单一目录、回测入口、自定义图配置、工作流 fixture | 本轮已复现问题有针对性回归；不修改业务门禁以让测试通过；明示真实能力范围。 |
| 第二阶段 统一数据与类型 | D1/D2 分母和地点、其余数据接口，ArtifactRef、SeriesSet/SelectionSet/FeatureMatrix、模型/政策注册 | 真实数据质量报告，类型/单位/频率/授权校验；可从稳定对象重放分析。 |
| 第三阶段 恢复可组合流水线 | DAG 编译执行、持久节点、近似扫描+AR/GBDT 演示、正式扫描与 LSTM 模型接入 | 先验不依赖 LSTM 的工程链，再验完整科学链；每一步来源一致、失败可恢复、写操作幂等。 |
| 第四阶段 专业预警和闭环 | 风险政策、域内复测、分级通知、事件及周期守护、SOP | 真实组织和渠道试点；告警时效、误报、送达、执行反馈及核销分别达标。 |
| 第五阶段 扩展专业模型 | 食源预测/溯源、环境模型/推演、慢病/筛查、OCR/视觉、完整报告 | 每技能提交专家金标准、真实外部留出及模型卡；达标后更新验证状态。 |

建议为每个技能增加三个独立字段：实现阶段（planned/partial/implemented）、验证阶段（contract/mock/observed-backtest/external/professional-approved）、数据就绪状态。保留执行 status 表示本次结果。它们回答不同问题，不应继续由一个 available 标记承担。

验收包至少包括：需求映射、数据字典和质量报告、算法及适用限制、schema 和版本、真实样例/金标准、独立指标和区间、权限/数据不足/取消/重试测试、AG-UI 与地图实际截图、通知及工单审计、运维负载及时效测试。分别验原子技能与端到端场景，既保证功能解耦，也保证可灵活串接。
