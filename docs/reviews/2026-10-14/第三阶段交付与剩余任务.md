# 第三阶段交付与剩余任务

2026 年 10 月 14 日。本阶段实现持久科学 DAG 和扫描到固定成员历史的工件链。通用动态组合工作流现标为“部分实现、工程契约已验证”；LSTM、包含 LSTM 的完整流水线及专业科学效果仍未验收。最新进展以本文件为准，第一、第二阶段报告保留历史记录。

科学节点只通过工件引用交换数据。模型和用户界面获得有限预览，不复制整张矩阵；服务端将已授权数据通过有字节预算的 stdin 交给路径无关的 Python 内核。输入最多 16 MiB、输出最多 8 MiB、单节点执行预算 120 秒；扫描最多 500 个地点和 999 次置换。现有 Text2SQL 的范围及行数门禁保持生效。

## 时间窗与来源规则

DAG 的 `scope` 是一次批准的根范围，包含时间、辖区、方法和可选物种过滤。节点不能增加辖区或改变方法；节点 `window` 只能落在根时间窗及提供测量值的上游窗口内。需要长历史时应在根 scope 中明确批准长历史，不能由扫描结果反向扩大读取权限。根截止日期也不能超过 DatasetRef 的 asOf。

成员工件的窗口表示“这批成员依据哪个时期被选出”；Measurements 的窗口表示“哪些时期的记录可用”。FeatureMatrix/SeriesSet 可以使用较早形成的成员集合与覆盖目标窗口的同一不可变 Measurements 快照。仓库及编译器都校验准确来源谱系和成员子集，且成员形成的 asOf 不能晚于目标工件 asOf，防止把未来选出的簇用于更早截止的模型评估。扫描和 K-Means 的窗口随本次实际计算保存。

工件仍校验同用户、组织、领域、角色、当前辖区、根批准范围、DatasetRef、内容哈希及依赖。任务提交保存完整 DatasetRef 清单；即使版本号未变，origin、asOf 或 schema 等元数据变化也会拒绝执行。认证 Worker 在每个节点开始及提交结果前重取当前账号；禁用、撤权、组织/角色/范围变化不会沿用旧身份提交结果。

独立调用生成的临时工件有效期仍为 24 小时。持久 DAG 生成的工件有效期固定为提交时起 7 天，且不晚于任何上游；恢复不会延长期限。过期输出不会被偷偷刷新或换成新的来源；检查点有效性错误会在状态中单独显示，恢复拒绝过期工件，需要以新 requestKey 重新提交当前来源任务。业务库备份可保留计划和检查点，但不代替工件授权与有效期。

科学节点只读来源并新增不可变工件。进程在写工件后、提交检查点前故障，可能留下未被引用的工件；检查点仍受租约保护，不承诺工件写入恰好一次。孤立工件清理列为剩余生命周期工作。

## 入口、拆分与目录

| 公开技能 | 职责 |
|---|---|
| `skill_composable_workflow` | 编译、提交、读取、取消、恢复持久科学 DAG；兼容别名 `skill_scientific_dag`。原 planned 能力的可执行子集改为 partial，避免另造一个重复的工作流展示入口。 |

| `skill_cluster_member_select` | ClusterSet→SelectionSet，按实际簇标签选取固定成员。 |

复用第二阶段的 Measurements、特征矩阵、历史序列和工件读取技能。原 `skill_satscan_spatial` 与 `skill_species_composition` 保持原来的直接查询、地图及描述统计语义；新的工件计算入口供串接使用，不隐式改变旧界面统计口径。新工件的地图发布暂属独立适配工作，空间目录声明为 non-spatial，避免把一个工件引用当成已验证地图图层。

当前 **68 个公开 ID、1 个内部 ID、104 个公开展示位置**：病媒 41、食源 20、环境 21、慢病 22；仍有 **17 个 planned ID、19 个 planned 展示位置**。科学 DAG 与内核均为 partial/contract，验收证据指向新测试；集市沿用服务端目录，没有把 Mock 成功或工程回归标成专业效果通过。

`skill_lstm_predictor` 和 `skill_satscan_kmeans_lstm` 保持 planned/unvalidated，编译器对 LSTM 节点返回 CAPABILITY_UNAVAILABLE。不存在可注册的已训练权重、scaler、输入特征/单位/频率版本和合格真实来源滚动回测，故本阶段没有创建假模型或随机预测。将来的 LSTM 接入必须同时验证权重/预处理哈希、SeriesSet 契约、截止及频率、固定成员、独立回测与留出证据；仅有 Mock 历史不足以放行。

## 补充数据及可复现用法

已生成的数据包位于工作区 `.mock-data/phase-three-scientific/`，包含四域只读快照、manifest、地域映射和隔离业务工件库；来源为 `mock`，并由 `.mock-data/audit/` 的生命周期登记、文件身份和内容哈希保护。该目录已加入 gitignore，生成脚本和示例计划纳入代码。默认 observed manifest 和现有四域源数据库没有切换或改写。Mock 仍禁止进入 pilot/正式业务；现有真实快照不足时应明确报告不足。

补充的病媒 profile 覆盖 2019 年 1 月至 2025 年 11 月的 83 个观测月份，每地点每月两个物种记录共享一个明确的布灯访次，投入为 8–10 trap-hours。金水区另有 4 个稳定地点 ID，在 2024 年 6 月形成可重复检测的同坐标热点；不因相同坐标合并成员。记录对访次的归属、方法、日期、单位和说明由生成器明确写入 `mock_scientific_visits`。适配器只有在 origin=mock、有真实生命周期标记且快照哈希通过时读取它；observed 数据仍须依据采样单登记，旧 sampling_unit 不被推断。

生成新的目录（已存在目录不会覆盖）：

```sh
./.venv/bin/python scripts/seed-scientific-dag.py \
  --output-dir .mock-data/new-scientific-bundle \
  --audit-dir .mock-data/audit --seed 42
```

示例计划：[scan-kmeans-history.json](../../../config/scientific-dags/scan-kmeans-history.json)。根授权历史为 2019-01-01 至 2025-10-31，扫描与矩阵窗口为 2024 年 6 月，三个探索性簇形成后按其固定成员回取月历史。改变 `cluster-select.params.labels` 可只回取指定实际簇；缺少成员走 SKIPPED 分支。

在本地/demo 终端设置环境后使用共享服务内核。CLI 只创建开发身份，pilot 必须通过已认证技能提交；不会绕过认证启用 CLI：

```sh
export DEPLOYMENT_TIER=local
export DATASET_MANIFEST_PATH="$PWD/.mock-data/phase-three-scientific/manifest.json"
export DATASET_REGION_BINDINGS_PATH="$PWD/.mock-data/phase-three-scientific/region-bindings.json"
export APP_BUSINESS_DB_PATH="$PWD/.mock-data/phase-three-scientific/business.db"
node scripts/scientific-dag.cjs compile config/scientific-dags/scan-kmeans-history.json
node scripts/scientific-dag.cjs submit config/scientific-dags/scan-kmeans-history.json my-request-1
# 用 submit 返回的 runId 替换 RUN_ID。
node scripts/scientific-dag.cjs status RUN_ID
node scripts/job-worker.cjs
# 也可每个独立进程只执行一个科学 tick：node scripts/scientific-dag.cjs work
# 控制：node scripts/scientific-dag.cjs cancel RUN_ID / resume RUN_ID
```

真实部署应备份目标业务库并通过既有迁移入口应用 011，沿用已完成的 009/010 和其校验和；正式 Worker 使用实时认证身份、observed 来源和当前地域映射。新增迁移已在隔离业务库、完整集成及备份恢复回归中验证。
