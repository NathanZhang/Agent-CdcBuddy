# 模型输入依赖与Mock启动隔离验证

本轮修复实测库缺少 `fact_vector_exposure` 导致种群预测被无关气象依赖阻断，以及底层SQL异常直接显示的问题。

## 修复范围

- 种群ARIMA/LSTM仅需要同一采样方法的捕获历史和有效采样投入；GBDT气象融合另需匹配温度、降雨，且不要求人口或基因列。预测时序缺月或未覆盖截止期明确停止，避免把过早月份的预测冒充用户目标期。
- 并发症关联不再要求风险分类器特征、两类结局或训练样本数；罕见死因聚集不再依赖区县人口；环境干预情景不再依赖活动/热浪字段；场所评级不再要求症状或到访人数。
- 抗药性模型排除缺失试验温度、缺少配对历史等无效样本，返回输入和排除数量；不把缺失数值填成零。知识检索和模板管理不再要求监测事实库可读。
- 通用读取校验按分支所需字段执行，缺表、字段、空范围、样本不足和不匹配时段返回中文；Python协议与TypeScript技能错误出口均避免向用户暴露底层SQL。旧历史分析卡片中的SQL缺表原因也转成中文，原存储记录不改写。
- `server.sh start all mock [包目录]` 显式创建或复用四域验收包，使用3101—3104、独立业务库、构建目录和各域Worker；`stop/status/restart all mock` 同样隔离。普通启动不自动从DataMock目录复制来源。Mock启动校验四域来源标记、生命周期、路径及链接，拒绝混入实测来源或将业务写入指向包外。

## 逐项检查

[54项矩阵](matrix.md)同时列出默认数据源缺项与Mock实际业务回归结果。默认数据源30项满足登记输入检查，22项不满足，1项需图片上传、1项OCR暂缓；计数检查满足不表示模型或业务验收成功。Mock输入检查为52项满足、1项图片输入、1项暂缓。

[业务回归证据](flow-verification.json)包含54项提示词、执行状态、技能及检查结果。本轮54项在真实技能、Python计算、业务持久化上逐项执行；意图、规划与汇总使用明确的协议替身，不能冒充本轮54次真实LLM研判。完整测试另验证普通工作台/浮窗组件渲染与7项持久业务闭环。此前真实模型54项证据在2026-10-14记录中，本轮不覆盖或改写。

缺数据故障测试遍历38个分析分支，分别注入缺表、缺字段；另验证没有气象表时实际ARIMA/LSTM训练及预测、仅气象列时GBDT训练、各无关依赖解除、空范围和历史SQL错误展示。测试源自独立SQLite夹具，未删除或修改实测库。

初轮回归发现生测温度缺失导致第25项不足，已修复为显式排除不完整样本并披露排除数量，复测通过。输入、完整业务、页面和专业效果分开计量。

## 运行与隔离

本次显式启动的可访问Mock包为 `.mock-data/input-audit-20261015`：

```sh
./server.sh start all mock .mock-data/input-audit-20261015
./server.sh status all mock
./server.sh stop all mock
```

病媒 http://localhost:3101，食源 http://localhost:3102，环境 http://localhost:3103，慢病 http://localhost:3104。默认实测病媒服务继续使用3001，未切换数据源。验收包有生命周期，过期后改用新目录生成。

[来源隔离证据](source-isolation.json)核对四个默认来源库与 `config/datasets.json` 的SHA-256，修复和Mock启动前后一致。来源不随Git发布，未把合成输入写入实测库。

OCR、短信/APP仍暂缓；60/61保留人工复核，完整WHO编码依赖正式Iris/MUSE；图片与环境采样仍需用户实际输入。Mock不代表专业精度或真实病例效果验收。
