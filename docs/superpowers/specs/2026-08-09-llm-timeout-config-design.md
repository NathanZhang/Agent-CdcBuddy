# LLM 超时环境变量配置设计

## 背景

生产环境中，SiliconFlow 的同一模型请求既可能在 1 秒内返回，也可能出现超过 20 秒的长尾响应。当前意图路由与 Text2SQL 分别使用写死的 4 秒和 2.5 秒超时，导致环境配置正确时仍频繁触发规则降级。

## 设计

- 意图路由读取 `SILICONFLOW_ROUTER_TIMEOUT_MS`，默认值为 `30000` 毫秒。
- Text2SQL 读取 `SILICONFLOW_TEXT2SQL_TIMEOUT_MS`，默认值为 `30000` 毫秒。
- 配置值必须是有限的正整数；缺失、非数字、零或负数均回退到默认值。
- 超时解析逻辑放在一个无副作用的小型工具模块中，两个调用点复用，避免产生不同的校验规则。
- `.env.example` 展示两个变量，生产环境继续通过 Compose 的现有 `env_file` 注入，无需修改 Compose 文件。

## 错误处理与兼容性

保持现有 `AbortController` 和规则降级机制不变。未配置新变量时，行为仅从原来的短超时调整为 30 秒；显式配置合法值时按配置执行。密钥、模型名、请求载荷及数据库行为均不改变。

## 验证

- 单元测试覆盖默认值、合法覆盖值以及非法值回退。
- 静态验证两个模型调用点均使用新解析函数。
- 完整执行项目构建与现有部署测试。
- 构建新的 Linux/amd64 镜像并在远程服务器重建容器。
- 通过远程业务接口确认请求不再在 4 秒时被主动中止，并检查容器健康状态及日志。
