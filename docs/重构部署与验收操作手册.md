# 重构部署与验收操作手册（2026-10-12）

本手册对应 codex/cdcbuddy-refactor 分支。旧部署文档中的自动 Mock 初始化、端口推断领域和固定预警示例不再适用。

## 部署参数与数据边界

部署等级 local / demo / pilot 独立于 NODE_ENV。生产环境未指定等级默认 pilot；Docker 与 Compose 默认 pilot。local/demo 可使用显式开发身份，不能用于多人真实数据试点。pilot 没有默认账户，业务请求必须具备服务端认证会话；每个请求重新读取用户权限，写操作校验 Origin 和 CSRF。

AGENT_DOMAIN 决定领域，不依赖端口。四域共享同一镜像，以各自参数启动。APP_ORIGIN 必须是实际访问地址；HTTPS 提供 Secure Cookie。当前认证是本地账户，不是机构 SSO。

config/datasets.json 配置四域来源；DATASET_MANIFEST_PATH 可切换受控快照。事实库只读挂载，业务库 APP_BUSINESS_DB_PATH 可写，不能把事实库作为业务库。当前病媒 observed、其他三域 mock。Mock 不降低计算和业务事务要求，也不代表真实效果已验收。

## 构建与启动

```sh
npm ci --no-audit --no-fund
python3.14 -m venv .venv
.venv/bin/pip install -r requirements.lock
./scripts/check-refactor.sh
npm run build
docker build -t agent-cdcbuddy:refactor .
docker compose up -d
```

Compose 要求显式 SILICONFLOW_API_KEY，避免写入 Git。基础镜像锁定 digest，Node 依赖使用 package-lock，Python 直接与传递依赖使用 requirements.lock。宿主 /app/data 挂载目录应可被容器 UID 1000 写入；事实文件应只读且存在。容器启动只执行业务 schema 迁移，不生成事实、账户、预警或工单。

版本迁移保存在 migrations/sqlite，_cdc_migrations 记录版本及 SHA256；并发迁移持有写锁、单次应用，校验已应用版本。失败会阻止启动。开发手动执行 node scripts/migrate.cjs；容器使用 node migrate.cjs。不要修改已经应用的迁移内容，应增加新版本。

显式 demo 数据初始化：DEPLOYMENT_TIER=demo .venv/bin/python scripts/seed-demo.py --domain foodborne --output /独立目录/food.db --seed 7。pilot 禁止调用该生成器；输出文件已存在则拒绝覆盖。

## 显式初始化账户

准备仅管理员可读的 JSON 文件，字段 username/password/role/organizationId/domainGrants/jurisdiction/professionalReview。密码至少12位；professionalReview 默认 false，组织管理权限不自动等于专业审批权。在隔离管理员环境运行 CDC_IDENTITY_FILE=/安全目录/identity.json node scripts/create-user.cjs，容器运行 node create-user.cjs。输入文件不得入库、入日志或入 Git，完成后从临时介质清理；没有默认生产口令。

身份 bootstrap 是部署运维入口。产品中的业务操作全部经过 Main Agent、实际 LLM 和 Skills。登录、退出、健康检查、状态传输及下载已授权文件字节属于基础协议入口。

## 健康检查与 Worker

/api/health/live 检查进程存活；/api/health/ready 检查本域事实 schema/integrity、业务迁移、LLM 配置，pilot 额外要求有效领域账户和 APP_ORIGIN。LLM 配置检查不代表外部模型服务实时可用；实际 turn 仍可能返回诚实失败。

Worker 是独立进程，执行同一个 main Agent。Compose worker 无 HTTP 端口，禁用 Web readiness healthcheck；以进程退出状态、持久 Job lease/attempt/error、Worker JSON 日志判断运行状态。失败任务有限重试；没有外部短信、APP 推送送达能力。

## 备份与恢复

先停止所有领域 Web 写入、审批和 Worker，防止业务库与独立 LangGraph checkpoint 快照错位；SQLite online backup 不能保证两个数据库在运行中跨库原子一致。

```sh
.venv/bin/python scripts/backup-business.py --db /独立数据目录/business.db --output-dir /新快照目录
```

快照包含 business.db、存在时的 checkpoints.db、各表计数 manifest.json，执行 integrity_check，数据库文件权限0600。恢复时在全新目录放置 business.db，checkpoint 放置为 business.db.checkpoints，保留来源只读快照，运行迁移校验后启动。恢复账户会话、真实运行记录、Job、审批、工单与通知去重键必须同时保留，不能只复制某张业务表。

## CI 与验收区别

GitHub engineering job 在 Ubuntu/Node22/Python3.14 环境运行合成 fixture、lint/TS、契约/科学/集成测试、生产构建和镜像构建。CI 生成的数据全部标记 Mock，包括合成病媒；不把合成病媒当作真实业务效果。

本地受控验收另运行 observed 快照回测、44项兼容回归、真实外部 LLM 的四域浏览器交互与导出、队列审批证据。44项兼容通过不等于54项业务需求完整，也不等于预测精度达标。查看 docs/reviews/2026-10-12 的阶段验收报告和最终交付记录。

## 重构验收环境与工单政策

本轮验收容器仅绑定localhost 9767–9770；试点边界容器9771/9772，账户均为临时隔离验收身份。业务与恢复证据工作文件在 .refactor-acceptance（Git/Docker忽略）；事实库仍是工作树只读副本。该环境不是生产部署。

Job的可核销采样政策必须显式 retestMeasurement={category,methodName,speciesName?}，原查询使用 captureRetestQuery(retestMeasurement,rule.field) 的规范AVG模板。模板原型：SELECT AVG(f.capture_count) AS "value" FROM fact_monitoring f JOIN dim_species s ON f.species_id=s.species_id JOIN dim_method m ON f.method_id=m.method_id WHERE s.category='蚊' AND m.method_name='诱蚊灯法'。city/district/from/to在operation-input.args中，必须与外层及身份范围一致。缺此政策的旧工单无法自动核销。专业审批可以在同组织、领域、辖区内由不同用户进行，不扩展普通所有者私有资源访问。

## 2.0发布合并中的部署兼容

生产Compose保留32112至32115四个默认端口和四域独立业务目录，增加对应的四个Worker。领域识别始终使用服务端注入配置，不按端口推断。镜像默认版本为2.0.0。

生产Compose插值配置deploy.env需提供VECTOR_ORIGIN、FOODBORNE_ORIGIN、ENV_ORIGIN、CHRONIC_ORIGIN，值必须为浏览器实际访问的协议、主机与端口；localhost默认值仅用于本机。远端部署脚本从RemoteHost与各域端口生成默认值；HTTPS或反向代理部署在deploy.config.ps1中显式设置VectorOrigin/FoodborneOrigin/EnvOrigin/ChronicOrigin。部署脚本仍负责文件/哈希/端口检查，正式试点需先配置LLM、组织账户与专业权限，再以/api/health/ready确认就绪；主页200不能代替就绪。Worker没有HTTP端口。

向量旧业务库由/app/data/app_business.db迁往/app/data/vector/app_business.db时，通过SQLite backup复制业务库和存在的.checkpoints，原件保留；新库已存在则不覆盖。迁移前必须停止旧实例及所有写入者，保证两份数据库处于一致的离线状态。启动进程用文件锁协调迁移，随后应用版本化迁移，不运行旧演示业务初始化器。

镜像构建保留NEXT_PUBLIC_TIANDITU_KEY参数。远端构建脚本要求明确浏览器地图key；Git不包含本地构建凭据。

## 地域与地图增量迁移（2026-10-13）

新增迁移 005、006、007 分别保存服务器意图/地图场景、带身份与范围的空间来源、查询快照；原有迁移未改写。升级前按本手册备份业务库及检查点，再运行迁移。历史未验证视图不能直接成为可复用空间来源；历史来源和导出每次重新校验当前角色、敏感列、辖区、所有权及来源版本。

本地目录只覆盖随仓库提供的河南边界；边界声明 EPSG:4490，监测来源经用户确认 WGS84 EPSG:4326。保留原生坐标声明，不声称完成测绘级转换。更换数据快照时必须同步提供 `DATASET_REGION_BINDINGS_PATH` 的版本绑定；未知版本、未知地域和无来源映射停止数据执行。界面底图范围与数据辖区分别批准，权限失败仍可保留独立公共行政底图。

自由文本默认启用 `LLM_REGION_INTENT_ENABLED`，关闭时拒绝自由文本，显式结构化 UI 与已冻结后台任务可继续受控执行。后台任务保存批准范围与查询绑定；重启后恢复并校验版本，不重新通过 LLM 解释“今年”等相对词。表格导出使用原 runId/callId 对应的已执行快照。

上线前运行 `npm test`、`npm run lint`、`npx tsc --noEmit`、`npm run build` 和 `node scripts/check-spatial-capability-coverage.mjs`，再在批准的模型服务上运行独立开发及留出评估。CI 的合成快照另行生成地域绑定，全部保留 Mock 来源。实际准确率和耗时以 [地域地图验收记录](reviews/2026-10-13/地域地图验收记录.md) 为准；工程测试不能替代模型识别验收或科学效果验收。
