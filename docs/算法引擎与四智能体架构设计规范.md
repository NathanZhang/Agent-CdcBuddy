## 三、 核心数学与深度学习模型算法原理

### 1. Kulldorff SaTScan 空间-时间扫描统计量
SaTScan 采用动态圆柱形扫描窗口 $Z$，底圆覆盖地理空间，高代表时间跨度。对于泊松模型，对数似然比 $LLR$ 公式如下：
$$LLR(Z) = \ln \left(\frac{c}{E[c]}\right)^c \left(\frac{C - c}{C - E[c]}\right)^{C - c} I\left(\frac{c}{E[c]} > 1\right)$$
其中：
- $C$ 为全域总观测捕获数，$c$ 为窗口 $Z$ 内观测捕获数；
- $E[c]$ 为窗口 $Z$ 内基于无效假设的期望捕获数；
- 统计量显著性通过 999 次蒙特卡洛随机置换检验获得经验 $P$ 值。

### 2. PyTorch 双向多变量 LSTM 深度时序模型
网络结构采用输入维度为 3 (密度, 气温, 湿度) 的双向多层 LSTM：
$$i_t = \sigma(W_{ii} x_t + b_{ii} + W_{hi} h_{t-1} + b_{hi})$$
$$f_t = \sigma(W_{if} x_t + b_{if} + W_{hf} h_{t-1} + b_{hf})$$
$$g_t = \tanh(W_{ig} x_t + b_{ig} + W_{hg} h_{t-1} + b_{hg})$$
$$o_t = \sigma(W_{io} x_t + b_{io} + W_{ho} h_{t-1} + b_{ho})$$
$$c_t = f_t \odot c_{t-1} + i_t \odot g_t$$
$$h_t = o_t \odot \tanh(c_t)$$
模型结合前向与后向隐藏状态 $H_t = [\overrightarrow{h_t}, \overleftarrow{h_t}]$，通过全连接层输出未来多步密度预测与置信上/下界。

### 3. Shannon-Wiener 物种多样性与均匀度
$$H' = -\sum_{i=1}^{S} P_i \ln(P_i), \quad J' = \frac{H'}{\ln(S)}$$

### 4. 综合传播风险动力学指数
$$R_{\text{trans}} = w_1 \cdot \min\left(100, \frac{D_{\text{obs}}}{D_{\text{base}}} \times 30\right) + w_2 \cdot (MIR \times 300) + w_3 \cdot S_{\text{climate}} + w_4 \cdot S_{\text{pop}}$$

## 四、 后台常驻守护智能体 (Daemon Agent) 与 Prompt Policy 机制

`daemon_surveillance.py` 实现了 7×24 小时后台运行机制：
1. **双轮驱动引擎**：
   - **定时巡检 (Interval)**：支持 60s ~ 3600s 动态可配置周期轮询；
   - **事件驱动 (Event-Driven)**：监听底层监测数据增量上报事件。
2. **Prompt-Driven Policy 动态注入**：
   - 疾控专家输入自然语言策略（如“进入豫南登革热关键期，重点监控信阳与南阳”）；
   - LLM 解析提取策略 JSON（关注城市、物种、敏感阈值倍数、推荐处方）；
   - 动态热重载注入后台守护进程，实时调整巡检与预警判定规则。

## 五、 数据库抽象层 (DAL) 与 LangGraph Checkpointer

```typescript
export interface IVectorDataProvider {
  getMonitoringSummary(filter: LocationFilter): Promise<MonitoringStats>;
  getPopulationDynamics(species: string, city: string): Promise<TrendPoint[]>;
  getResistanceMatrix(species: string, pesticide?: string): Promise<ResistanceRecord[]>;

```
- **开发与演示环境**：基于 SQLite (`vector_monitoring.db` + `app_business.db`)；
- **生产与信创环境**：基于 PostgreSQL 14+ / 人大金仓 KingbaseES V8/V9；
- **LangGraph Checkpointer**：采用 `SqliteSaver` / `PostgresSaver` 支持复杂长链条计算的状态回溯与人机协同 (Human-in-the-Loop Interrupt)。
