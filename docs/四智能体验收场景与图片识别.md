## 架构取舍

- 54项只是一组需求对应的固化提示词。模型根据提示词生成任务并按需组合技能；每次调用都经过现有授权、意图范围、参数和来源校验。不存在独立场景执行技能。
- Python公共模块只承载数据筛选、拟合、留出验证和序列预测；领域模块保留各自公式及解释。模型训练与知识推理不会塞入UI或提示词。
- 报告和模板共用一套服务、所有者权限及乐观版本锁；环境采样共用API和业务表，不把离线缓存写回受保护的监测快照。
- 分级指数与核查任务分别标注实际指标、单位和阈值。环境任务覆盖饮水、PM2.5及高温异常；任务/审批/通知/复测复用既有Job、Outbox和Ticket，不增加另一套工作流。
- 死因60使用用户提供的2,047项三位类目解析原文，保留否定、歧义和来源。61沿用同一技能接入 Iris/MUSE，移除演示因果边；没有真实引擎时明确返回待配置，不生成根本死因候选。保持 ICD-10，详细配置见接入说明。

## 病媒现场图片识别API（35）

设置 `SILICONFLOW_VISION_MODEL` 为当前服务实际支持图片输入的模型ID，沿用已有 `SILICONFLOW_BASE_URL` 和 `SILICONFLOW_API_KEY`。本机配置的 `qwen3.8-27b` 已通过真实图片调用；`.env.local` 已增加视觉模型设置。正式环境通过env_file设置，不将密钥暴露到浏览器。

`POST /api/v1/mobile/detect-species`，Content-Type为application/json：

```json
{"imageDataUrl":"data:image/png;base64,<图片Base64>"}
```

支持JPEG、PNG、WebP，原始字节最大4MiB。接口限制请求字节数、检查Data URL和文件头；不抓取任意远程图片URL。认证模式须携带现有会话Cookie、匹配的Origin和 `X-CSRF-Token`。仅病媒领域专业角色可调用。

成功返回HTTP 200，`data`包括：

```json
{
  "type":"SPECIES_RECOGNITION_RESULT",
  "recognitionId":"服务端生成的UUID",
  "imageSha256":"图片内容哈希",
  "model":"实际模型ID",
  "speciesName":"白纹伊蚊",
  "category":"蚊",
  "confidence":0.82,
  "reason":"模型返回的可见形态依据与不确定性",
  "requiresReview":true,
  "expiresAt":1792064088926
}
```

以上物种及置信度仅为接口结构示例，不是本次实测结果。无法识别时名称、类别和置信度可为null，不返回固定物种/概率。实际空白图测试返回null并说明未见生物形态。模型拒绝、不可用或字段不合法时返回失败，且不产生成功识别记录。

前端通过实际文件选择/拍照输入上传，将模型候选回填到可编辑表单。识别完成后继续调用现有 `/api/v1/mobile/validate` 与 `/api/v1/mobile/record`，在原有record字段中携带 `recognitionId`。例如：

```json
{
  "city":"郑州市","district":"金水区","category":"蚊",
  "speciesName":"人工确认的物种","captureCount":1,
  "weatherTemp":25,"methodName":"诱蚊灯法",
  "recognitionId":"上一步返回的UUID"
}
```

服务端核对识别记录的用户、组织、领域和24小时有效期，持久化原始候选/置信度、人工确认物种和识别编号。客户端不能用自报置信度替代服务端记录。低温高捕获等现有质控规则继续阻止异常提交；记录进入SUBMITTED审核状态，不自动进入实测监测库。识别阶段仅保存图片哈希及结构化结果，不长期保存原始图片。

升级业务库需应用新增 `013_species_recognitions.sql` 和 `014_requirements_workflows.sql`；原有迁移不修改。移动识别准确率、物种覆盖和真实照片质量阈值留待后续调试评测。环境移动助手（58）包含扫码、离线及任务同步，不能用病媒图片接口充当完整实现。
