# 病媒生物监测预警智能应用全量真实功能开发方案与实施计划 (已更新数据隔离架构)

## 概述

本项目基于 `Agent-CdcBuddy-DataMock/vector_monitoring.db` 现有的 **5.6万+ 条多维病媒生态监测事实表、病原体检测表与抗药性测定表**，全面替换现有前端及服务端的 Mock/假数据与伪算法，构建一套**完全由真实数据驱动、具备真实科学计算与机器学习推断能力**的疾控病媒生物监测预警智能体系统。

> [!IMPORTANT]
> **数据库物理隔离设计原则**：
> 严格遵循**“分析数据集与业务应用数据物理分离”**原则。原始监测数据集库（`vector_monitoring.db`）作为只读数据资产库，仅用于多维查询、特征工程与模型训练；所有业务流转数据、工单状态、移动端上报记录、知识库与自定义技能均存放在**独立新建的应用业务数据库（`app_business.db`）**中，杜绝共库耦合。

## 数据库双库物理隔离设计

### 1. 监测数据集库（只读数据资产）: `vector_monitoring.db`
- **定位**：CDC 历史与当期监测数据湖/数据仓库。
- **权限**：应用服务与分析引擎仅以 `readonly` 模式连接。
- **包含表**：
  - `fact_monitoring`（生态监测事实表）
  - `fact_pathogen_detection`（病原核酸检测事实表）
  - `fact_insecticide_resistance`（杀虫剂抗药性测定事实表）
  - `dim_location`, `dim_species`, `dim_date`, `dim_environment`, `dim_method`, `dim_pesticide`, `dim_pathogen`, `dim_audit`

### 2. 独立业务数据库（可读写应用库）: `app_business.db`
- **定位**：支撑业务流程运转、状态机流转、用户交互沉淀与多模态扩展。
- **权限**：读写支持事务保障。
- **包含表设计**：
  1. `biz_disposal_tickets`（消杀与处置工单流转表）：
     - `ticket_id`, `alert_id`, `target_city`, `target_district`, `target_street`, `vector_category`, `species_name`, `severity_level`
     - `recommended_protocol_json`, `assigned_team`, `contact_phone`, `disposal_status` (PENDING / IN_PROGRESS / EVALUATING / RESOLVED)
     - `created_at`, `updated_at`, `resolved_at`, `before_density`, `after_bi_index`, `disposal_notes`
  2. `biz_early_warning_events`（预警事件触发与归档表）：
     - `event_id`, `title`, `level`, `trigger_source`, `trigger_reason`, `latitude`, `longitude`, `affected_population`, `push_status`, `push_payload_json`
  3. `biz_mobile_submissions`（移动端采集上报与审核流转表）：
     - `submission_id`, `user_id`, `location_text`, `latitude`, `longitude`, `image_url_base64`, `ai_recognized_species`, `ai_confidence`
     - `field_capture_count`, `weather_temp`, `weather_humidity`, `habitat_type`, `audit_status` (SUBMITTED / APPROVED / REJECTED), `auditor_comment`
  4. `biz_kb_standards`（国家标准与防治技术指南知识库表）：
     - `doc_id`, `doc_title`, `standard_no`, `category`, `chapter`, `content`, `keywords`, `embedding_vector`
  5. `biz_generated_reports`（自动生成专题报告归档表）：
     - `report_id`, `report_title`, `city`, `district`, `cycle_start`, `cycle_end`, `content_markdown`, `summary`, `created_at`
  6. `biz_custom_skills`（用户在会话中构建的元技能注册表）：
     - `skill_id`, `name`, `description`, `sql_query`, `chart_type`, `created_by`, `created_at`

## 逐项功能真实落地技术方案 (序号 23 ~ 35)

### 1. 种群动态模型 (No. 23)
- **技术方案**：
  - 数据源：`vector_monitoring.db` 历史按月/按旬聚合时序。
  - 模型实现：利用 Python `statsmodels.tsa.arima.model.ARIMA` / `SARIMAX`，以气温和湿度作为外生变量，对历史序列进行自回归拟合。
  - 输出指标：未来 1~3 个月真实预测曲线、95% 置信区间上下限、真实拟合优度 $R^2$ 与检验误差率。

### 2. 种群识别模型 (No. 24)
- **技术方案**：
  - 数据源：`vector_monitoring.db` 提取各区县、生境、月份下的多物种捕获量特征矩阵。
  - 模型实现：采用 `sklearn.cluster.KMeans` 对病媒群落空间分布进行聚类，自动判定优势种群特征与生态分布聚集簇。
  - 输出指标：各物种真实构成比、各市空间分布差异、Shannon-Wiener 多样性指数、K-Means 聚类中心画像。

### 3. 抗药性预测模型 (No. 25)
- **技术方案**：
  - 数据源：`vector_monitoring.db` 中的 LC50、校正死亡率、药剂类型、地理坐标及历史年度。
  - 模型实现：训练 `RandomForestClassifier` 分类器，以药剂类型、区县、历史死亡率趋势为特征，预测目标物种对特定药剂的耐药等级（敏感/低抗/中抗/高抗）。
  - 输出指标：真实预测耐药等级、预测置信度概率分布，并自动匹配《抗药性治理指南》推荐轮换药剂。

### 4. 病原携带风险评估模型 (No. 26)
- **技术方案**：
  - 数据源：关联 `vector_monitoring.db` 的病原检测、生态监测与生境事实。
  - 模型实现：运行 `mlxtend.frequent_patterns.apriori` / `fpgrowth`，挖掘 “【物种=白纹伊蚊】+【生境=居民区】+【季节=夏季】 $\rightarrow$ 【登革病毒=阳性】” 的高风险频繁项集与关联规则。
  - 输出指标：真实 Support（支持度）、Confidence（置信度）、Lift（提升度）排序列表。

### 5. 动态预警分析与 GIS 空间插值 (No. 27)
- **技术方案**：
  - 数据源：`vector_monitoring.db` 监测点位，预警触发后写入 `app_business.db` 的 `biz_early_warning_events`。
  - 模型实现：基于 `scipy.spatial` 实现 **IDW（反距离加权插值）** 算法，在全省及各市网格上生成连续平滑的密度与风险栅格热力矩阵；结合三级阈值（黄/橙/红）自动过滤街道级预警点。
  - 输出指标：空间插值热力网格、街道级预警点位列表、受影响人口真实空间叠加计算。

### 6. 预警推送信息与通道集成 (No. 28)
- **技术方案**：
  - 数据源：`app_business.db` 中的 `biz_early_warning_events`。
  - 实现：按风险等级（一般/较重/严重）匹配分级推送策略；记录短信网关 payload、移动端 Push 消息体与预警依据至独立业务库。

### 7. 处置闭环流转引擎 (No. 29)
- **技术方案**：
  - 数据持久化：读写 `app_business.db` 中的 `biz_disposal_tickets`。
  - 业务状态机：支持 `待派发 (PENDING)` $\rightarrow$ `处置中 (IN_PROGRESS)` $\rightarrow$ `复测评估 (EVALUATING)` $\rightarrow$ `自动核销/闭环 (RESOLVED)`。
  - 处置建议生成：根据预警物种与生境类型，自动关联国家标准库中的处置方案，前端支持一键派单、更新状态与回填 BI 复测指数。

### 8. 密度预测 GBDT 模型 (No. 30)
- **技术方案**：
  - 数据源：`vector_monitoring.db` 提取滞后 1~2 期密度、旬平均气温、降雨天数、相对湿度等特征。
  - 模型实现：采用 `sklearn.ensemble.HistGradientBoostingRegressor` 训练密度回归模型。
  - 输出指标：真实模型预测未来 1~2 个月密度、特征重要性排序（Feature Importance 真实权重贡献占比）。

### 9. 传染病传播风险评估模型 (No. 31)
- **技术方案**：
  - 数学模型：构建多因子定量传播风险指数：
    $$RiskScore = 100 \times \left( w_1 \cdot \tilde{D} + w_2 \cdot \tilde{P} + w_3 \cdot \tilde{E} + w_4 \cdot \tilde{C} \right)$$
    其中 $\tilde{D}$ 为归一化病媒密度指数，$\tilde{P}$ 为病原阳性率，$\tilde{E}$ 为常住人口密度指数，$\tilde{C}$ 为气温降雨适宜度指数。
  - 输出指标：各区县多维雷达图分解得分、传播风险等级划分、驱动因子归因分析。

### 10. 抗药性演化贝叶斯预测模型 (No. 32)
- **技术方案**：
  - 数学模型：基于历史年度抗性倍数与药剂使用频次，构建**马尔可夫转移概率与贝叶斯更新模型**，推算抗性基因（如 KDR 击倒抗性突变等位基因）在未来 1 年内的频率演变趋势。
  - 输出指标：未来各年度基因频率预测曲线、抗性倍数增长上限、耐药暴发预警期。

### 11. 自然语言问答 RAG 知识库检索 (No. 33)
- **技术方案**：
  - 知识库构建：录入国家标准文本至 `app_business.db` 中的 `biz_kb_standards`。
  - 检索增强：基于 BM25 / 轻量文本 Embedding + 语义相似度召回最相关的标准条款，注入大模型 Prompt，实现精准溯源与专业问答，响应时间 $\le 2$ 秒。

### 12. 专题报告自动撰写引擎 (No. 34)
- **技术方案**：
  - 数据提取：从 `vector_monitoring.db` 动态统计选定区域/周期的全量数据（捕获总量、同比环比、优势物种排名、抗药性、高风险预警点位）。
  - 内容生成：将真实统计聚合 JSON 注入大模型报告撰写 Prompt 动态撰写深度研判文字，报告归档至 `app_business.db` 的 `biz_generated_reports`，支持导出。

### 13. 移动端智能辅助与数据闭环 (No. 35)
- **技术方案**：
  - 物种图像识别：对接 Vision 大模型 API（如 Qwen-VL），对上传的现场照片进行形态学特征多标签识别与置信度打分。
  - 现场数据入库：`POST /api/v1/mobile/record` 接口写入 `app_business.db` 中的 `biz_mobile_submissions`，支持市级审核流转。
  - 实时质控校验：结合气温物理阈值与生境历史分布区间，进行多规则联动校验。

## 验证与测试计划

1. **数据库隔离验证**：
   - 验证对 `vector_monitoring.db` 的操作完全为只读（Readonly 模式，拒绝写入）；
   - 验证所有工单流转、上报记录、自定义技能均写入 `app_business.db`，数据互不干扰。
2. **算法真实性验证**：
   - ARIMA 时序预测真实输出未来月份值与置信区间；
   - K-Means 真实输出聚类中心与物种群落；
   - GBDT 真实输出气温、降雨等特征重要性权重分布。
3. **业务闭环验证**：
   - 预警触发 $\rightarrow$ 派发工单 $\rightarrow$ 状态更新 $\rightarrow$ BI复测 $\rightarrow$ 自动核销；
   - 移动端拍照上传 $\rightarrow$ Vision 识别物种 $\rightarrow$ 写入待审表 $\rightarrow$ 审核通过。
