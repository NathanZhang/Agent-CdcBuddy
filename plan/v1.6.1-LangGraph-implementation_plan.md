# 基于 LangGraph 的 CdcBuddy 智能体系统升级实施方案 (v2.0)

本方案旨在将 **Agent-CdcBuddy (疾控病媒生物监测预警智能体平台)** 从原有的“单轮路由/同步 Tool-Calling 架构”全面升级为**“基于 LangGraph 的有状态、多智能体协同与复杂多步计算编排体系”**。

升级后系统将具备：
1. **自主后台常驻多智能体（Daemon Agent）**：系统启动即自动在后台持续巡检、分析多维病媒数据，支持**定时轮询（可配置/热重载）**与**数据变更事件驱动（CDC/Hook）**双模式，支持**通过自然语言提示词动态调整巡检研判策略**，自发生成分级预警并推送到异步消息队列。
2. **多步长链条科学计算流水线（Stateful Multi-step Graph）**：支持复杂的算法级联调用（如 `SaTScan 时空扫描` ➔ `K-Means 特征分群` ➔ `LSTM 时序外推预测`），具备状态持久化、条件回退与人机协同审核（Human-in-the-Loop）能力。

## 🚀 二、 场景一方案：后台常驻数据分析智能体与自动预警推送 (深度设计)

针对用户关切的 **“定期间隔可配置”**、**“提示词设置修改任务逻辑”** 以及 **“数据变更事件驱动实现”**，设计如下专项机制：

### 1. 定期间隔与运行参数的配置机制 (Configurable Polling)

#### (1) 双层配置架构（静态配置 + 运行时热加载）
- **静态配置层（文件/环境变量）**：
  在 `config/daemon_config.yaml` 或 `.env.local` 中定义基础参数：
  ```yaml
  # config/daemon_config.yaml
  surveillance_daemon:
    enabled: true
    trigger_mode: "hybrid"            # "interval" | "event_driven" | "hybrid"
    interval_seconds: 300            # 默认轮询间隔 (5分钟)
    cron_expression: "*/5 * * * *"   # Cron 表达式 (可选)
    batch_size: 1000                 # 单次增量拉取最大记录数
    alert_push_queue: "redis://localhost:6379/0:cdc_alert_stream"
    active_prompt_profile: "summer_mosquito_peak" # 激活的研判提示词策略模板
  ```
- **运行时动态热加载 (Hot-reloading via REST API)**：
  FastAPI 后台暴露管理端点：
  - `GET /api/v1/daemon/config`：获取当前运行周期、触发模式及激活策略。
  - `POST /api/v1/daemon/config`：在线动态更新间隔时间（如从 300s 修改为 60s），后台 `asyncio.Event` 或调度器即刻无缝生效，无需重启后端服务。

### 3. 数据变更事件驱动 (Event-Driven Ingestion) 的具体实现

为了在有新监测数据产生时（如移动端 APP 采集上报、PCR 实验室批量录入、外部系统 API 推送）**毫秒级触发智能体**，而非苦等固定定时轮询，设计三级事件触发机制：

```
┌───────────────────────────────┐     ┌───────────────────────────────┐
│ 移动端采集上报 / 批量数据导入  │     │  第三方 CDC 监测系统 API 推送 │
└──────────────┬────────────────┘     └──────────────┬────────────────┘
               │                                     │
               ▼                                     ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 1. 应用层事件钩子 (Application Event Hook)                          │
│    在业务写入 DB 成功后，同步触发: event_bus.publish("DATA_CHANGED") │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 2. 数据库级 CDC 捕获 (Change Data Capture) - 兜底通道               │
│    • PostgreSQL / 人大金仓: 触发器执行 NOTIFY cdc_monitoring_channel│
│    • SQLite 模式: 基于 SQLite Update Hook / 文件变更监听 (Watchdog)  │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 3. 统一事件分发通道 (Redis Stream / asyncio.Queue)                  │
│    Payload: { "event": "NEW_DATA", "batch_id": "B-202408-01", ... } │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 4. LangGraph Daemon 接收事件并立即唤醒执行                          │
│    • 定时器被即刻重置                                               │
│    • 携带变更增量 (Delta Records) 直接运行 Graph 异常检测与预警流水线│
└─────────────────────────────────────────────────────────────────────┘
```

#### 事件驱动核心代码架构 (`backend/daemon/event_listener.py`):
```python
import asyncio
from typing import AsyncGenerator
import redis.asyncio as aioredis
from langgraph.graph import CompiledGraph

class SurveillanceDaemonRunner:
    def __init__(self, graph: CompiledGraph, interval: int = 300):
        self.graph = graph
        self.interval = interval
        self.is_running = False
        self.redis_client = None
        self.wake_event = asyncio.Event()

    async def start(self):
        self.is_running = True
        self.redis_client = aioredis.from_url("redis://localhost:6379/0")
        
        # 启动后台事件监听协程 (Event-Driven Listener)
        asyncio.create_task(self._listen_cdc_events())
        
        # 主调度循环 (Hybrid Timer + Event Trigger)
        while self.is_running:
            try:
                # 执行 LangGraph 监控与预警流
                await self._execute_surveillance_cycle()
                
                # 挂起等待：满足 interval 超时 或 收到 wake_event (数据变更事件)
                try:
                    await asyncio.wait_for(self.wake_event.wait(), timeout=self.interval)
                    self.wake_event.clear() # 被外部事件唤醒
                except asyncio.TimeoutError:
                    pass # 定时器正常触发
            except Exception as e:
                print(f"[Daemon Error] 巡检智能体执行异常: {e}")
                await asyncio.sleep(10)

    async def _listen_cdc_events(self):
        """监听 Redis Streams 数据变更消息"""
        pubsub = self.redis_client.pubsub()
        await pubsub.subscribe("cdc_monitoring_data_channel")
        async for message in pubsub.listen():
            if message["type"] == "message":
                print(f"[CDC Event] 接收到数据变更事件，立即唤醒后台智能体研判: {message['data']}")
                self.wake_event.set() # 唤醒主调度器立即执行
```

## 🔬 三、 场景二方案：多步复杂分析工作流 (SaTScan ➔ K-Means ➔ LSTM)

### 1. 业务目标
用户在对话框或控制台输入类似：“*调用 SaTScan 分析2022年3月全省的蚊媒密度分布，并将高风险区域的数据导入 LSTM 进行下一周的趋势预测*”。
系统通过 LangGraph 构建**有状态的科学计算图 (Stateful Scientific Pipeline Graph)**，精准执行：
$$\text{数据抽取与质控} \longrightarrow \text{SaTScan 时空扫描聚类} \longrightarrow \text{K-Means 风险亚群特征画像} \longrightarrow \text{LSTM 深度时序外推} \longrightarrow \text{AG-UI 渲染}$$

### 2. Pipeline Graph 状态定义 (State Schema)
```python
# app/agents/analytics_pipeline/state.py
from typing import TypedDict, List, Dict, Any, Optional
from pydantic import BaseModel, Field

class ScientificPipelineInput(BaseModel):
    target_year: int = 2022
    target_month: int = 3
    category: str = "蚊"
    species: Optional[str] = "白纹伊蚊"
    cluster_significance_p: float = 0.05
    forecast_horizon_days: int = 7

class ScientificPipelineState(TypedDict):
    # 输入与上下文
    input_params: ScientificPipelineInput
    chat_history: List[Dict[str, Any]]
    
    # 步骤 1: 原始抽取数据
    extracted_spatial_data: List[Dict[str, Any]]
    spatial_summary: Dict[str, Any]
    
    # 步骤 2: SaTScan 扫描结果
    satscan_clusters: List[Dict[str, Any]]
    satscan_significant_areas: List[str] # 识别出的高风险市/县列表
    satscan_llr_statistics: Dict[str, Any]
    
    # 步骤 3: K-Means 分群结果
    kmeans_clusters: List[Dict[str, Any]]
    kmeans_feature_centers: Dict[int, Dict[str, float]]
    
    # 步骤 4: LSTM 预测结果
    lstm_time_series_predictions: Dict[str, List[Dict[str, Any]]] # 各高风险区域未来7天预测序列
    lstm_confidence_intervals: Dict[str, Dict[str, List[float]]]
    
    # 步骤 5: 人机协同与最终呈现
    requires_expert_review: bool
    review_status: str # "pending" | "approved" | "rejected"
    generative_ui_payload: Dict[str, Any] # 传递给 AG-UI 前端渲染的组合数据结构
    execution_logs: List[str]
```

### 3. Graph 拓扑结构与节点实现细节

```
        ┌─────────────────────────┐
        │  1. Data Extract Node   │ (从 vector_monitoring.db 抽取 2022-03 密度与气象)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   2. SaTScan Node       │ (运行圆形/椭圆空间扫描，计算 LLR 与 p-value 显著聚类)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   3. K-Means Node       │ (对高风险聚类点按环境/积水/密度多维特征进行亚群剖析)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   4. LSTM Predict Node  │ (将聚类高风险历史序列注入 LSTM 模型，外推未来7天曲线)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │ 5. HIL Expert Review    │ ───[风险 > 阈值]───► 【挂起中断】等待专家确认/调整参数
        │  (Conditional Interrupt)│
        └────────────┬────────────┘
                     ▼ (通过 / 默认放行)
        ┌─────────────────────────┐
        │ 6. AG-UI Synthesis Node │ (封装 Tianditu GIS 图层 + ECharts 预测图 + 研判公报)
        └─────────────────────────┘
```

#### 各节点核心功能定义：
1. **`Data Extract Node` (`node_data_extract`)**：
   - 构造参数化 SQL，从 `vector_monitoring.db` 提取 2022 年 3 月全省 18 地市所有监测点（诱蚊诱卵器法、二氧化碳幼虫法）的密度值、经纬度、水体生境与同期气温、湿度。
2. **`SaTScan Node` (`node_satscan_cluster`)**：
   - 调用 `analytics_engine/satscan_cluster.py` 算法。
   - 使用 Poisson 时空扫描统计量（Spatio-temporal Scan Statistics），设定最大扫描半径（如全省人口/面积的 30%）。
   - 计算各候选窗口的对数似然比（LLR）与 Monte Carlo 模拟 $p$ 值，过滤出 $p < 0.05$ 的一类核心聚集区（如信阳市、驻马店市、郑州市金水区）与二类次级聚集区。
3. **`K-Means Node` (`node_kmeans_subgrouping`)**：
   - 调用 `analytics_engine/species_clustering.py`。
   - 提取高风险聚集区内部的多维特征向量：$[\text{蚊幼指数}, \text{成蚊捕获密度}, \text{降水日数}, \text{地表温度}, \text{旧城老旧小区占比}]$。
   - 聚为 $k=3$ 类典型风险亚群（如：“暴雨渍水高发群”、“老旧居民区容器孳生群”、“公园水系扩散群”），赋予针对性防制标签。
4. **`LSTM Predict Node` (`node_lstm_timeseries_forecast`)**：
   - 调用 `analytics_engine/lstm_predictor.py`。
   - 取出上述识别出的高风险区域过去 60 天的历史滑动时间序列。
   - 载入预训练的双层 LSTM 神经网络（PyTorch / ONNX），结合未来 7 天天气预报输入，外推输出各高风险区域未来 7 天的每日预测密度点估计及 95% 置信区间上/下界。
5. **`HIL Gate Node` (`node_expert_review_gate`)**：
   - 若预测未来一周蚊媒密度指数超过暴发警戒线（如布雷图指数 $\text{BI} > 20$ 或诱蚊诱卵指数 $\text{MOI} > 15$），调用 LangGraph 的 `interrupt()` 挂起执行。
   - 将中间态推至前端，提示：“*模型预测郑州市金水区未来 5 天内将突破红色预警警戒值，是否直接生成应急处置派单？*”，待疾控专家在前端点击“确认”或“调整参数”后再恢复执行。
6. **`AG-UI Synthesis Node` (`node_ui_synthesis`)**：
   - 将 SaTScan 聚类圆环/多边形、K-Means 分群标签、LSTM 7 天带状置信区间预测曲线整合为标准化 AG-UI 前端数据契约。

## 💡 五、 方案总结与核心价值

1. **“定时巡检 + 数据变更”双轮驱动**：既支持配置文件与 API 动态调整轮询间隔，又支持数据写入时的事件驱动即刻唤醒，兼顾系统资源消耗与告警时效性。
2. **“提示词即策略”赋予极高定制自由度**：疾控专家通过自然语言指令即可动态切换夏秋季登革热、冬春季鼠媒等研判逻辑，底层算法流水线自动根据提示词裁剪执行。
3. **“重型科学计算链”稳定编排**：原生支持 `SaTScan`、`K-Means`、`LSTM` 等重型计算工具的高阶级联，解决了状态共享、断点恢复与人机协同审核问题。
