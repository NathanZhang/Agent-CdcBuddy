# 基于 LangGraph 的 CdcBuddy 智能体系统升级实施方案

本方案旨在将 **Agent-CdcBuddy (疾控病媒生物监测预警智能体平台)** 从原有的“单轮路由/同步 Tool-Calling 架构”全面升级为**“基于 LangGraph 的有状态、多智能体协同与复杂多步计算编排体系”**。

升级后系统将具备：
1. **自主后台常驻多智能体（Daemon Agent）**：系统启动即自动在后台持续巡检、分析多维病媒数据，自发生成分级预警并推送到异步消息队列与前端总线。
2. **多步长链条科学计算流水线（Stateful Multi-step Graph）**：支持复杂的算法级联调用（如 `SaTScan 时空扫描` ➔ `K-Means 特征分群` ➔ `LSTM 时序外推预测`），具备状态持久化、条件回退与人机协同审核（Human-in-the-Loop）能力。

## 🚀 二、 场景一方案：后台常驻数据分析智能体与自动预警推送

### 1. 业务目标
系统启动后，后台自动拉起 **Surveillance Daemon Agent**，定期（如每 5 分钟或通过数据变更事件驱动）扫描最新监测数据，执行异常检测与多智能体风险综合研判，自动生成结构化预警事件（含等级、核心区域、处置方案），并将事件推送到消息队列（Redis / 内存队列），通过 SSE 实时推送到前端通知栏与 GIS 预警脉冲图层。

### 2. LangGraph Daemon 状态机定义
```python
# app/agents/daemon/state.py
from typing import TypedDict, List, Dict, Any, Optional
from datetime import datetime

class DaemonMonitoringState(TypedDict):
    last_checked_timestamp: str
    new_monitoring_batches: List[Dict[str, Any]]
    detected_anomalies: List[Dict[str, Any]]
    evaluated_risks: List[Dict[str, Any]]
    generated_alerts: List[Dict[str, Any]]
    dispatch_results: List[Dict[str, Any]]
    interval_seconds: int
    cycle_count: int
    error_log: Optional[str]
```

### 3. Daemon Graph 节点构成
1. **`ingest_monitoring_data`**：
   - 提取增量监测数据（或全省近期滑动窗口 7 天内的蚊媒、蝇类、鼠类数据）。
   - 关联当前气象参数（气温、降雨量、相对湿度）。
2. **`detect_anomalies`**：
   - 采用统计过程控制（SPC）与自适应 Poisson / GBDT 残差阈值检测，判断区域密度是否存在激增（Spike）。
   - 条件路由：若 `len(detected_anomalies) == 0`，跳转至 `wait_interval`；否则进入 `evaluate_risk_multi_agent`。
3. **`evaluate_risk_multi_agent` (多智能体协同评估)**：
   - **风险评估智能体 (Risk Agent)**：结合 PCR 病原携带率（登革热/乙脑/疟原虫）与人口密度计算综合风险指数 $R_{\text{trans}} \in [0, 100]$。
   - **抗药性分析智能体 (Resistance Agent)**：同步匹配该区域优势种对拟除虫菊酯、有机磷的抗药性评级。
4. **`synthesize_alert_events`**：
   - 生成符合 `biz_early_warning_events` 规范的预警实体：
     - `alert_id`: 自动生成唯一编码，如 `ALERT-202408-901`
     - `level`: `red` ($R \ge 70$) / `orange` ($40 \le R < 70$) / `yellow` ($R < 40$)
     - `geojson_polygon`: 疫点空间范围多边形
     - `disposal_advice`: 结合 GB/T 标准推荐的消杀药剂与复测计划
5. **`push_to_message_queue`**：
   - 写入持久化业务库 `biz_early_warning_events`。
   - 推送至 Redis 队列通道 `cdc_alert_stream` 或 Python 异步广播通道。
   - 前端通过 `/api/v1/alerts/sse` 实时接收，界面弹出高危告警卡片并触发 GIS 地图红闪脉冲。
6. **`wait_interval`**：
   - 异步休眠设定间隔（如 `asyncio.sleep(interval)`），随后循环回环至 `ingest_monitoring_data`，实现 7×24 小时永真守护。

## 🔬 三、 场景二方案：多步复杂分析工作流 (SaTScan ➔ K-Means ➔ LSTM)

### 1. 业务目标
用户在对话框或控制台输入类似：“*调用 SaTScan 分析2022年3月全省的蚊媒密度分布，并将高风险区域的数据导入 LSTM 进行下一周的趋势预测*”。
系统通过 LangGraph 构建**有状态的科学计算图 (Stateful Scientific Pipeline Graph)**，精准执行：
$$\text{数据抽取与质控} \longrightarrow \text{SaTScan 时空扫描聚类} \longrightarrow \text{K-Means 风险亚群特征画像} \longrightarrow \text{LSTM 深度时序外推} \longrightarrow \text{AG-UI 渲染}$$

### 2. Pipeline Graph 状态定义 (State Schema)
```python
# app/agents/analytics_pipeline/state.py
from typing import TypedDict, List, Dict, Any, Optional
from pydantic import BaseModel, Field

class ScientificPipelineInput(BaseModel):
    target_year: int = 2022
    target_month: int = 3
    category: str = "蚊"
    species: Optional[str] = "白纹伊蚊"
    cluster_significance_p: float = 0.05
    forecast_horizon_days: int = 7

class ScientificPipelineState(TypedDict):
    # 输入与上下文
    input_params: ScientificPipelineInput
    chat_history: List[Dict[str, Any]]
    
    # 步骤 1: 原始抽取数据
    extracted_spatial_data: List[Dict[str, Any]]
    spatial_summary: Dict[str, Any]
    
    # 步骤 2: SaTScan 扫描结果
    satscan_clusters: List[Dict[str, Any]]
    satscan_significant_areas: List[str] # 识别出的高风险市/县列表
    satscan_llr_statistics: Dict[str, Any]
    
    # 步骤 3: K-Means 分群结果
    kmeans_clusters: List[Dict[str, Any]]
    kmeans_feature_centers: Dict[int, Dict[str, float]]
    
    # 步骤 4: LSTM 预测结果
    lstm_time_series_predictions: Dict[str, List[Dict[str, Any]]] # 各高风险区域未来7天预测序列
    lstm_confidence_intervals: Dict[str, Dict[str, List[float]]]
    
    # 步骤 5: 人机协同与最终呈现
    requires_expert_review: bool
    review_status: str # "pending" | "approved" | "rejected"
    generative_ui_payload: Dict[str, Any] # 传递给 AG-UI 前端渲染的组合数据结构
    execution_logs: List[str]
```

### 3. Graph 拓扑结构与节点实现细节

```
        ┌─────────────────────────┐
        │  1. Data Extract Node   │ (从 vector_monitoring.db 抽取 2022-03 密度与气象)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   2. SaTScan Node       │ (运行圆形/椭圆空间扫描，计算 LLR 与 p-value 显著聚类)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   3. K-Means Node       │ (对高风险聚类点按环境/积水/密度多维特征进行亚群剖析)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │   4. LSTM Predict Node  │ (将聚类高风险历史序列注入 LSTM 模型，外推未来7天曲线)
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │ 5. HIL Expert Review    │ ───[风险 > 阈值]───► 【挂起中断】等待专家确认/调整参数
        │  (Conditional Interrupt)│
        └────────────┬────────────┘
                     ▼ (通过 / 默认放行)
        ┌─────────────────────────┐
        │ 6. AG-UI Synthesis Node │ (封装 Tianditu GIS 图层 + ECharts 预测图 + 研判公报)
        └─────────────────────────┘
```

#### 各节点核心功能定义：
1. **`Data Extract Node` (`node_data_extract`)**：
   - 构造参数化 SQL，从 `vector_monitoring.db` 提取 2022 年 3 月全省 18 地市所有监测点（诱蚊诱卵器法、二氧化碳幼虫法）的密度值、经纬度、水体生境与同期气温、湿度。
2. **`SaTScan Node` (`node_satscan_cluster`)**：
   - 调用 `analytics_engine/satscan_cluster.py` 算法。
   - 使用 Poisson 时空扫描统计量（Spatio-temporal Scan Statistics），设定最大扫描半径（如全省人口/面积的 30%）。
   - 计算各候选窗口的对数似然比（LLR）与 Monte Carlo 模拟 $p$ 值，过滤出 $p < 0.05$ 的一类核心聚集区（如信阳市、驻马店市、郑州市金水区）与二类次级聚集区。
3. **`K-Means Node` (`node_kmeans_subgrouping`)**：
   - 调用 `analytics_engine/species_clustering.py`。
   - 提取高风险聚集区内部的多维特征向量：$[\text{蚊幼指数}, \text{成蚊捕获密度}, \text{降水日数}, \text{地表温度}, \text{旧城老旧小区占比}]$。
   - 聚为 $k=3$ 类典型风险亚群（如：“暴雨渍水高发群”、“老旧居民区容器孳生群”、“公园水系扩散群”），赋予针对性防制标签。
4. **`LSTM Predict Node` (`node_lstm_timeseries_forecast`)**：
   - 调用 `analytics_engine/lstm_predictor.py`。
   - 取出上述识别出的高风险区域过去 60 天的历史滑动时间序列。
   - 载入预训练的双层 LSTM 神经网络（PyTorch / ONNX），结合未来 7 天天气预报输入，外推输出各高风险区域未来 7 天的每日预测密度点估计及 95% 置信区间上/下界。
5. **`HIL Gate Node` (`node_expert_review_gate`)**：
   - 若预测未来一周蚊媒密度指数超过暴发警戒线（如布雷图指数 $\text{BI} > 20$ 或诱蚊诱卵指数 $\text{MOI} > 15$），调用 LangGraph 的 `interrupt()` 挂起执行。
   - 将中间态推至前端，提示：“*模型预测郑州市金水区未来 5 天内将突破红色预警警戒值，是否直接生成应急处置派单？*”，待疾控专家在前端点击“确认”或“调整参数”后再恢复执行。
6. **`AG-UI Synthesis Node` (`node_ui_synthesis`)**：
   - 将 SaTScan 聚类圆环/多边形、K-Means 分群标签、LSTM 7 天带状置信区间预测曲线整合为标准化 AG-UI 前端数据契约。
   - 返回给前端组件 `VectorAnalysisMultiStepCard`，实现地图与图表的联动高亮展示。

## 💻 四、 核心代码架构实现示例

### 1. Python 后端 LangGraph 主图编排 (`backend/graphs/vector_satscan_lstm.py`)

```python
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver
from app.agents.analytics_pipeline.state import ScientificPipelineState
from analytics_engine.satscan_cluster import run_satscan_spatial_scan
from analytics_engine.species_clustering import run_kmeans_feature_clustering
from analytics_engine.lstm_predictor import run_lstm_short_term_forecast

def extract_data_step(state: ScientificPipelineState) -> dict:
    params = state["input_params"]
    # 模拟/真实执行 SQL 抽取
    records = query_vector_monitoring_db(
        year=params.target_year, 
        month=params.target_month, 
        category=params.category
    )
    return {
        "extracted_spatial_data": records,
        "execution_logs": state.get("execution_logs", []) + [f"已抽取 {params.target_year}年{params.target_month}月 全省 {len(records)} 条病媒监测记录"]
    }

def satscan_step(state: ScientificPipelineState) -> dict:
    data = state["extracted_spatial_data"]
    # 运行 SaTScan 空间聚集性扫描
    satscan_res = run_satscan_spatial_scan(data, p_threshold=state["input_params"].cluster_significance_p)
    return {
        "satscan_clusters": satscan_res["clusters"],
        "satscan_significant_areas": satscan_res["high_risk_cities"],
        "satscan_llr_statistics": satscan_res["statistics"],
        "execution_logs": state.get("execution_logs", []) + [f"SaTScan 扫描完成，识别出 {len(satscan_res['clusters'])} 个显著高风险聚集簇(p<0.05)"]
    }

def kmeans_step(state: ScientificPipelineState) -> dict:
    clusters_data = state["satscan_clusters"]
    # 针对高风险区域多维生态特征执行 K-Means 分群
    kmeans_res = run_kmeans_feature_clustering(clusters_data, n_clusters=3)
    return {
        "kmeans_clusters": kmeans_res["clustered_items"],
        "kmeans_feature_centers": kmeans_res["centroids"],
        "execution_logs": state.get("execution_logs", []) + ["K-Means 特征分群完成，完成3类风险亚群剖析"]
    }

def lstm_step(state: ScientificPipelineState) -> dict:
    high_risk_areas = state["satscan_significant_areas"]
    # 对所有高风险区域提取历史时序并运行 LSTM
    lstm_res = run_lstm_short_term_forecast(
        high_risk_areas, 
        horizon_days=state["input_params"].forecast_horizon_days
    )
    
    # 检查是否超过极端阈值需要专家介入 (Human-in-the-loop)
    exceeds_threshold = any(v["max_predicted_density"] > 20.0 for v in lstm_res.values())
    
    return {
        "lstm_time_series_predictions": lstm_res["predictions"],
        "lstm_confidence_intervals": lstm_res["confidence_intervals"],
        "requires_expert_review": exceeds_threshold,
        "execution_logs": state.get("execution_logs", []) + [f"LSTM 深度时序预测完成，输出未来 {state['input_params'].forecast_horizon_days} 天趋势曲线"]
    }

def check_expert_review_condition(state: ScientificPipelineState) -> str:
    if state.get("requires_expert_review") and state.get("review_status") != "approved":
        return "human_review"
    return "ui_synthesis"

def human_review_step(state: ScientificPipelineState) -> dict:
    # 触发 LangGraph 中断，挂起等待外部输入
    # 在前端审核通过后，传入 review_status="approved" 恢复执行
    return {"review_status": "pending"}

def ui_synthesis_step(state: ScientificPipelineState) -> dict:
    # 组装最终 AG-UI 综合渲染结构
    ui_payload = {
        "viewType": "SATSCAN_KMEANS_LSTM_PIPELINE",
        "title": f"{state['input_params'].target_year}年{state['input_params'].target_month}月全省蚊媒时空扫描与LSTM预测报告",
        "mapData": {
            "satscanClusters": state["satscan_clusters"],
            "highRiskCentroids": state["satscan_significant_areas"]
        },
        "clusteringData": {
            "groups": state["kmeans_clusters"],
            "centers": state["kmeans_feature_centers"]
        },
        "forecastData": {
            "series": state["lstm_time_series_predictions"],
            "ci": state["lstm_confidence_intervals"]
        },
        "logs": state["execution_logs"]
    }
    return {"generative_ui_payload": ui_payload}

# 构建图拓扑
builder = StateGraph(ScientificPipelineState)
builder.add_node("data_extract", extract_data_step)
builder.add_node("satscan_scan", satscan_step)
builder.add_node("kmeans_cluster", kmeans_step)
builder.add_node("lstm_forecast", lstm_step)
builder.add_node("human_review", human_review_step)
builder.add_node("ui_synthesis", ui_synthesis_step)

builder.add_edge(START, "data_extract")
builder.add_edge("data_extract", "satscan_scan")
builder.add_edge("satscan_scan", "kmeans_cluster")
builder.add_edge("kmeans_cluster", "lstm_forecast")
builder.add_conditional_edges(
    "lstm_forecast", 
    check_expert_review_condition, 
    {
        "human_review": "human_review",
        "ui_synthesis": "ui_synthesis"
    }
)
builder.add_edge("human_review", "ui_synthesis")
builder.add_edge("ui_synthesis", END)

# 编译 Graph 并绑定持久化 Checkpointer
checkpointer = SqliteSaver.from_conn_string("app_business.db")
spatial_lstm_pipeline_graph = builder.compile(
    checkpointer=checkpointer,
```

## 💡 六、 方案总结与核心价值

1. **从“被动问答”进化为“主动守护”**：后台数据分析智能体打破了传统 AI 必须等待人类提问的局限，实现了数据接入 ➔ 自动研判 ➔ 异常捕捉 ➔ 队列分发的 24 小时全天候主动预警。
2. **从“单步工具”进化为“复杂科学工作流”**：原生支持 `SaTScan`、`K-Means`、`LSTM` 等重型计算工具的高阶级联，解决了参数在多步之间的状态共享、数据清洗与错误断点恢复问题。
3. **安全可控的人机协同 (Human-in-the-Loop)**：通过 LangGraph 的 Checkpointing 与 Interrupt 机制，确保高风险预警和重大消杀指令必须经疾控专家在线审核确认，严防大模型幻觉与误判风险。
