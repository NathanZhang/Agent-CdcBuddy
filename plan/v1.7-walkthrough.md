# 意图分析与调度重构完成总结

我们已经成功按照通用智能体（Agent）的 Tool Use 设计理念，重构了系统的意图分析与调度流程。同时，对前端的 `DataTableComponent` 组件进行了重大升级，完美解决了原先复合指令和上下文指代无法做后续统计计算的问题。

---

## 变更内容概述

### 1. 意图路由层 (`llm-router.ts`)
- 删除了原有的前置正则表达式等硬编码硬拦截逻辑（如 `isMultiStepChain`, `isDataQueryVerb`）。
- 将意图分流与参数提取的判定权完全移交给大模型的原生 Function Call 机制，让模型根据技能的描述 schema 自由、灵活地决策应该调用何种技能，大幅提升复杂/模糊查询的识别准确度。

### 2. 服务端 Agent 循环与上下文指代消解 (`route.ts` BFF 接口)
- 在接口中引入了 **Agent Tool Use 执行循环**：
  1. **意图路由**：第一轮 LLM 请求决定需要执行的 Tool。
  2. **工具执行**：在服务端执行目标技能（例如查表）。
  3. **反馈注入**：若返回大列表，自动提取关键的 **统计学元数据（样本量、均值、求和、温湿度均值）** 及样本数据作为 Tool 运行反馈，注入消息链，避免上下文爆炸并提供高阶数据视野。
  4. **二次生成**：再次请求 LLM，生成富含具体数据统计（如：“捕获数量的平均值为 14.85 只/台次”）的自然语言最终回答。
- **指代消解**：在接收到包含“上述/当前数据/该表”等涉及“计算/统计”的请求时，自动将当前活动视图 `context.currentView.data` 提取出来，转换为统计特征注入大模型的 System Prompt。使得大模型无需重复调用 Tool 重新执行 SQL，即可秒级回复统计分析结果，且保持左侧工作区的数据表状态不被销毁。

### 3. 数据表格可视化卡片升级 (`DataTableComponent.tsx`)
- 在表格上方新增动态、高质感、高颜值的 **统计摘要指标卡片 (KPI cards)**：
  - **监测样本量** (条)
  - **平均捕获量** (只/台次)
  - **总捕获数量** (只)
  - **单次最高值** (只/台次)
  - **平均气温 / 相对湿度** (℃ / %)
- 具备前端自动统计与自适应降级：即使后端数据不带 `summaryStats`，前端也能在加载 `data` 数组时通过 `useMemo` 实时完成多维统计计算并渲染，保障了功能的健壮度。
- 加入了 Hover 变焦、高透毛玻璃卡片和细微微动效，使得整体界面呈现出极佳的视觉质感。
